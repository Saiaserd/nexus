# 0005：連結／標籤擷取方式與索引資料庫位置

- 日期：2026-10-25
- 狀態：已採用
- 決定者：PM / CTO

## 背景
M2 要解析每篇筆記的 `[[雙向連結]]` 與 `#標籤`，存進 SQLite，並提供反向連結與全文搜尋。PLAN 的技術選型裡有 md4c。不過 T-104 已經完成逐行的 `MarkdownLexer`，它能辨識程式碼區塊、行內程式碼、wiki link 與標籤，給語法高亮使用。

另外，M1 的 UI 在等作者確認設計稿；為了不讓開發停下來，PM 決定先做 M2 不需要 UI 的核心層（T-201、T-202）。

## 選項
### 連結與標籤擷取
1. **沿用 `MarkdownLexer`**：編輯器上了色的連結，就是索引裡的連結，兩邊行為保證一致；不需要再寫一套規則。
2. **用 md4c 的 `MD_FLAG_WIKILINKS`**：比較接近 CommonMark；但 md4c 不認得標籤，wiki link 的細節（`|別名`、`#標題`）也和 lexer 不同，會出現「畫面上是連結、索引裡卻沒有」的落差。

### 索引資料庫位置
1. **`<vault>/.nexus/index.sqlite`**：跟著 vault 走；T-101 本來就會略過 `.` 開頭的資料夾，不會被當成筆記。
2. 使用者設定資料夾（`%APPDATA%`）：vault 搬家後就對不上，而且要另外做 vault 與資料庫的對應。

### SQLite 存取
1. **sqlite3 C API（vcpkg，含 fts5）加上自己寫的 RAII 包裝**：確定有 FTS5；版本由 vcpkg 釘住。
2. QtSql：Qt 內建的 SQLite 編譯選項不受我們控制，FTS5 不一定開啟。

## 決定
- 連結與標籤擷取**沿用 `MarkdownLexer`**；另外補上 lexer 沒處理的 frontmatter（`---` 區塊中的 `tags:`、`aliases:`）。md4c 保留給日後的預覽或匯出使用。
- 索引放在 **`<vault>/.nexus/index.sqlite`**。它是快取，刪掉後可以完全重建；要在 vault 的 `.gitignore` 範本中提示忽略。
- SQLite 用 **C API 加上 RAII 包裝**（`src/storage`），每個執行緒各自一個連線，開 WAL 模式。

## 理由
- 高亮與索引的規則只有一套，使用者看到的就是系統認定的。
- 索引跟著 vault 走，搬家、同步都不會壞，壞了刪掉就能重建。
- 確保 FTS5 一定可用，達成 PLAN 的「搜尋 < 50ms」。
