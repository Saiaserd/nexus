# 0004：核心層的路徑表示與檔案 I/O

- 日期：2026-10-25
- 狀態：已採用
- 決定者：PM / CTO

## 背景
M1 的核心層（Vault 掃描、筆記讀寫、檔案監看、Markdown 標記解析）會被 UI 層大量使用。CLAUDE.md 允許核心層使用「標準函式庫與必要的 QtCore」。如果不先統一，路徑型別（`std::filesystem::path` 與 `QString` 混用）、編碼和換行處理都會在各模組各做一套。

## 選項
1. **全部用標準函式庫**（`std::filesystem`、`std::fstream`）：不依賴 Qt。但 Windows 上的 path 與 UTF-8 轉換很容易出錯；也沒有原子寫入和資源回收筒，要自己用 Win32 API 實作。
2. **核心層用 QtCore**（`QString`、`QDir`、`QFile`、`QSaveFile`、`QFileSystemWatcher`）：與 UI 直接相容，跨平台的細節由 Qt 處理。
3. 兩者混用：介面不一致。

## 決定
採用選項 2，並遵守以下規則：

- **路徑**：一律用 `QString`。vault 內的筆記用「相對於 vault 根目錄、以 `/` 分隔」的相對路徑識別（例如 `specs/vault-管理.md`），只有呼叫檔案系統時才轉成絕對路徑。
- **文字內容**：記憶體中一律是 `QString`，換行統一為 `\n`。讀檔時記住原本的換行（LF / CRLF）以及有沒有 UTF-8 BOM，寫回時還原，不讓 Nexus 默默改掉使用者檔案的格式。
- **寫入**：用 `QSaveFile` 原子寫入，避免寫到一半當機留下壞檔。
- **刪除**：用 `QFile::moveToTrash` 移到資源回收筒。平台不支援時回傳錯誤，不自動改成永久刪除。
- **錯誤**：可失敗的函式回傳 `nexus::Expected<T, nexus::FileError>`（或該模組的錯誤型別）。錯誤用列舉加上路徑，**核心層不產生給使用者看的中文訊息**，文案由 UI 層負責。
- **Markdown 標記解析**（給語法高亮用）：輸入 `QStringView`，回傳的位置以 UTF-16 code unit 計算，直接對應 `QSyntaxHighlighter`。
- **QObject**：只有需要 signal 的類別才繼承 `QObject`（例如 `VaultWatcher`）。其餘保持純值型別，方便測試。

## 理由
- UI 是 Qt，核心層用同一套字串與路徑型別，交界處不用轉換，也就不會因此出錯。
- 原子寫入、資源回收筒、檔案監看 QtCore 都有現成、跨平台的實作。
- 核心層仍然不依賴 Widgets，可以單元測試。

## 補充（2026-10-25，T-102 審核）
- 同一個檔案混用 LF 和 CRLF 時，寫回會統一成占多數的那種，不逐行保留。這種檔案極少見，逐行記錄換行的複雜度不划算。單一換行種類的檔案一律逐 byte 還原。
- 以 `.` 開頭的檔名或資料夾名稱，`validateName` 要拒絕（T-105）：Vault 掃描會把它們當成隱藏而略過，建立後使用者會看不到。
