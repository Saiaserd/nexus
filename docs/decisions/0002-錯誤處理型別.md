# 0002：錯誤處理型別（std::expected 與 C++20 的衝突）

- 日期：2026-10-25
- 狀態：已採用
- 決定者：PM / CTO

## 背景
PLAN.md 定語言為 C++20，但 CLAUDE.md 規範「可失敗的函式回傳 `std::expected`」。`std::expected` 是 C++23 標準庫功能：

- MSVC 14.42（VS 17.12）只在 `/std:c++latest` 下提供 `std::expected`，該模式不保證穩定。
- GCC 需 12+ 且 `-std=c++23`；Ubuntu 預設 Clang 搭配 libstdc++ 時支援度依版本而定。

## 選項
1. 升級到 C++23：可直接用 `std::expected`；但 MSVC 必須用 `/std:c++latest`，CI 三個編譯器支援度不一致。
2. 維持 C++20，使用 `tl::expected`（vcpkg `tl-expected`，header-only，API 與 `std::expected` 幾乎相同）。
3. 自寫 Result 型別：需自行維護與測試，沒有必要。

## 決定
採用選項 2。

- 在 `src/core/Expected.h` 定義：
  `namespace nexus { template <class T, class E> using Expected = tl::expected<T, E>; using tl::unexpected; }`
- 專案內只使用 `nexus::Expected` / `nexus::unexpected`，不直接寫 `tl::`，以便日後切換。

## 理由
- 三個編譯器在 C++20 下都穩定，嚴格警告與 sanitizer 不會被實驗性模式干擾。
- 介面相容，日後三平台都穩定支援 C++23 時，只需改別名即可遷移到 `std::expected`（屆時另立 ADR）。
